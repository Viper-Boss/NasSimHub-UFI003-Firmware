# 呼叫编号与重启

ModemManager 的 `/Call/0`、`/Call/1` 是当前服务实例里的对象编号。设备、D-Bus 或 ModemManager 重启后，编号可能再次出现。不能直接用这个编号关联长期通话记录、命令去重、浏览器控制租约或音频流。

MSM8916 后端现在向外提供 `mm-<lifetime>-<index>`。lifetime 是启动标识、D-Bus 实例标识和 ModemManager 唯一服务 owner 的 SHA-256 截断摘要。它不包含电话号码、SIM 标识、密钥或短信正文。同一个存活呼叫保持同一个 ID；重启后复用的对象编号属于另一通呼叫。

读取呼叫列表时，在读取前后核对 lifetime。中途换代则返回不可用，避免把两个服务实例的数据拼成一份快照。接听、挂断和 DTMF 必须携带当前 lifetime；旧编号返回未找到。生产 D-Bus 控制操作以核对过的唯一 owner 为目标，服务重启不会把旧命令转发给新服务中的同号对象。PCM 层支持新编号格式，HTTP 层仍检查完整编号是否对应真实、存活的呼叫。

NAS 将 Node 呼叫 ID 作为不透明值使用。新编号不会碰撞升级前的历史记录；旧记录保留，不通过清空历史或关闭控制租约来规避冲突。部署前须结束当前通话。

回归测试覆盖设备/总线/服务重启、读取中途换代、旧编号拒绝控制、拨号回执和来电列表一致性，以及新编号打开、关闭 PCM 进程。现场通过 NAS API 连续拨号和挂断，确认记录时间、控制权和终止状态。真实浏览器的界面、麦克风和对端听感需要另行验收。
